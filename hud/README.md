# Native Hermes HUD

`index.html` is the interactive client. Serve the repository over localhost or HTTPS; file URLs cannot fetch the avatar pack or record a microphone. The page loads the bundled placeholder avatar pack `../simulator/avatar/default/manifest.json` and its atlas; `?avatar=<pack folder or manifest.json URL>` loads another pack in the same format (see [`../docs/avatar-packs.md`](../docs/avatar-packs.md)). Screen content is an opaque 600×300 canvas. The avatar cell is drawn at 192×288 at (4,6). Every letter is drawn with integer rectangles from the included 5×7 bitmap font at scale 2; no DOM text or `fillText` enters the display. The surrounding controls are normal accessible HTML and do not enter recordings.

The response uses 31 columns and 14 lines, word wrapping and splitting long tokens. Multi-page responses show `< 1/3 >` at the bottom; single pages have no footer. Arrow keys or the outside Previous / Next controls change pages. Capturing voice keeps the exact response and current page visible, changes the avatar to listening, and adds a compact microphone indicator. Hold Space outside the text field, or hold the talk button, then release to send. Microphone capture needs a supported browser and permission. Browser SpeechRecognition is preferred; availability and processing depend on the browser. Otherwise, MediaRecorder is enabled only when `/api/capabilities` declares transcription available, and the returned transcript is submitted as a normal chat message. Unsupported voice capture is disabled visibly; text input remains usable.

## Backend adapter

By default, the client sends `POST /api/chat` with `{message,session_id}`. JSON results accept `{text,session_id,events}`; each normalized event is applied before the final text. A backend may instead return `application/x-ndjson` events: `session` updates `session_id`, `event` maps its `status` to activity, `delta` accumulates response text while the previous response remains readable, and `result` installs final `text`. Normalized events also work: `status` with `status`, `response` with `text`, `append` with `text`, `emote` with `animationId` and optional `hold`, `done`, and `error` with `message`. `status` values include thinking, working, searching, remembering, saving, delegating, speaking, waiting, idle and error. Lifecycle events must come from actual execution hooks. The model router remains backend-owned. Server transcription, when enabled by a truthy `transcription`, `audio`, or `audio_transcription` capability, uses `POST /api/audio` multipart `audio`; a JSON `{transcript}` or `{text}` result then goes through `/api/chat`.

Set `window.HUD_CONFIG={apiBase:'/other/api'}` before the inline startup script to change the endpoint prefix. Alternatively set `window.HUD_ADAPTER={async sendText(message,{turnId,onEvent}), async sendAudio(blob,{turnId,onEvent})}`; call `onEvent` for real lifecycle transitions and final response. A turn ID protects the reducer from stale prior-turn events. Error details appear below the screen while preserving the last response. The frontend has no credentials or model settings.

Chat requests advertise NDJSON so tool lifecycle events drive the avatar while the previous response stays readable. A stream without a final result is an explicit failure and never silently completes. The final reply plays one speaking cycle before returning to idle; a newer turn or recording preempts that completion. Conversation IDs persist in localStorage when the browser permits it; the outside **New conversation** button clears the ID and starts fresh without changing router configuration.

## Renderer API for demo compositions

Load `hud.js`; it exports `window.HermesHUD` (and CommonJS for reducer checks). Construct `new HermesHUD(canvas,{pack,atlas,scenario})`, where `pack` is a schema-1 avatar manifest and `atlas` its decoded image. Or `await hud.load({packUrl})`, which fetches the manifest and atlas once; nothing loads during frame rendering.

`hud.render(state,timeSeconds)` draws one deterministic frame. State fields are `output`, `page`, `avatar` (a state name such as `thinking`), `avatarSince`, `status`, and optional `responsePages` (authored page strings). `hud.renderAt(timeSeconds,scenario)` accepts `{beats:[{start,duration,avatar,response,input,pageIndex,status,responsePages?}]}`; `output`/`page` aliases and legacy numeric `animationId` values are also accepted. It returns the active beat snapshot. `avatarSince` defaults to beat start, or can retain a continuous clip across beats. Frame timing, loop/once policies and fallbacks come from the pack, exactly as on the glasses. Explicit hold emotes retain the last frame; non-hold one-shot emotes return to the underlying activity after their clip. Listening preempts emotes. Seeking is deterministic and requires no timers.

`HermesHUD.drawText(ctx,text,x,y,{scale:2,lineHeight:18})` draws external demo input at the same pixel resolution. Composite the 600×300 canvas onto a native parent canvas at integer coordinates and apply nearest-neighbor scaling only after the whole image is complete. `HermesHUD.renderHUD(ctx,state,pack,atlas,time)` is the pure drawing function, `paginate(text)` returns pages of wrapped lines, and `reducer(state,event)` implements live state changes without changing response/page on listening or activity transitions. Typography intentionally normalizes to uppercase ASCII; unsupported glyphs render as `?` rather than silently disappearing.

Run `node hud/test_hud.cjs` to check pagination retention while recording, transport lifecycle mapping, partial-stream preservation, stale turn and completion rejection, explicit failure retention, native pixel coordinates, scenario fitting and client syntax.
